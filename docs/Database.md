# 🗄 Database

## Overview

FlowForge uses **Microsoft SQL Server** as its primary relational database and **Entity Framework Core** as the Object-Relational Mapper (ORM).

The database is designed around the application's domain model, with relationships that closely mirror real-world project management concepts such as organizations, projects, boards, work items, comments, and users.

---

# Database Provider

- Microsoft SQL Server
- Entity Framework Core
- Code-First Migrations

The database schema is managed through Entity Framework Core migrations, allowing changes to be version-controlled and applied consistently across different environments.

---

# Main Entities

The core data model consists of the following entities.

| Entity | Description |
|---------|-------------|
| **Organization** | Represents a workspace containing users, projects and boards. |
| **User** | Represents an authenticated user within an organization. |
| **Project** | Groups related boards under a common objective. |
| **Board** | Represents a Kanban board within a project. |
| **Column** | Defines workflow stages such as To Do, In Progress and Done. |
| **WorkItem** | Represents an individual task or work item. |
| **Comment** | Stores discussions associated with work items. |
| **Notification** | Stores user notifications generated by application events. |
| **ActivityHistory** | Maintains an audit trail of important actions performed within the system. |

---

# Entity Relationships

The high-level relationship between entities is shown below.

```

Organization
│
├── Users
├── Projects
│ └── Boards
│ └── Columns
│ └── WorkItems
│ └── Comments
│
└── Notifications

```

This hierarchy provides clear ownership of data and simplifies authorization throughout the application.

---

# Multi-Tenant Design

FlowForge follows a **multi-organization** architecture.

Each organization owns its own:

- Users
- Projects
- Boards
- Work Items
- Notifications

This allows multiple organizations to share the same application while keeping their data isolated.

---

# Entity Framework Core

Entity Framework Core is responsible for:

- Database access
- Relationship mapping
- Change tracking
- LINQ queries
- Migrations

Business logic remains in the Application layer, while Infrastructure handles persistence through EF Core.

---

# Migrations

Database schema changes are managed using EF Core migrations.

Typical workflow:

```

Update Domain

↓

Update DbContext

↓

Create Migration

↓

Apply Migration

```

This ensures the database remains synchronized with the application's domain model.

---

# Data Integrity

FlowForge relies on several mechanisms to maintain data consistency:

- Foreign key relationships
- Required constraints
- Fluent API configuration
- Business rule validation
- Optimistic application flow through CQRS handlers

Validation is performed before data reaches the database whenever possible.

---

# Summary

The database is designed around the application's domain model, using SQL Server and Entity Framework Core to provide a reliable, scalable, and maintainable persistence layer while supporting future growth of the platform.
