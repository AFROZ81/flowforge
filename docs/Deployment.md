# Deployment

## Production shape

FlowForge is deployed as one same-origin site on MonsterASP.NET:

```text
https://flowforge-app.runasp.net
  ├── /                 React SPA and PWA assets
  ├── /api/…            ASP.NET Core controllers
  ├── /hubs/…           SignalR
  └── /health           API + SQL Server health check
```

The API and SPA share the same origin, so production does not need a wildcard CORS policy.

## Required configuration

Set these in the hosting panel or as environment variables:

| Variable | Value / purpose |
| --- | --- |
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `ConnectionStrings__DefaultConnection` | Production SQL Server connection with encryption. |
| `Jwt__Key` | Strong random signing key, at least 32 characters. |
| `Jwt__Issuer` | `FlowForgeAPI` |
| `Jwt__Audience` | `FlowForgeClient` |
| `Jwt__ExpiryInMinutes` | Optional; defaults to 480. |
| `Frontend__BaseUrl` | Optional override; defaults to `https://flowforge-app.runasp.net`. |

Do not deploy the local SQL Server connection string or placeholder JWT key from `appsettings.json`.

## Invitation links

Invitation links are environment-specific:

- `appsettings.Development.json` → `http://localhost:5173`
- `appsettings.json` → `https://flowforge-app.runasp.net`
- `Frontend__BaseUrl` overrides both

A trailing slash is normalized. Existing emailed links are immutable; resend an invitation to generate a link with the current base URL.

## SMTP

Invitation delivery uses `SmtpEmailService`. Configure:

```text
SMTP_HOST
SMTP_PORT
SMTP_USER
SMTP_PASS              (or SMTP_KEY)
SMTP_FROM_EMAIL
SMTP_FROM_NAME
SMTP_TIMEOUT_SECONDS
SMTP_ENABLE_SSL
```

If SMTP is unavailable, the invitation is still stored with a failed delivery status and can be resent. Admins can verify configuration through `GET /api/Invitations/smtp-diagnostics`.

## Database migrations

Migrations are committed. Apply them before or with the deployment:

```powershell
dotnet ef database update --project backend/src/FlowForge/FlowForge.Infrastructure --startup-project backend/src/FlowForge/FlowForge.API
```

For a remote database, allow the deploying machine's IP in the provider firewall or run the generated SQL script through the hosting panel.

## Frontend build

`frontend/.env.production` uses a same-origin API URL:

```ini
VITE_API_URL=/api
```

Build and copy the generated assets into the API's `wwwroot` before publishing:

```powershell
npm --prefix frontend run build
```

The PWA manifest, icons, service worker, and runtime caches are generated by the Vite PWA plugin. Rebuild the bundle whenever frontend code changes.

## Storage

The active attachment provider is local disk under:

```text
FlowForge.API/Storage/Attachments
```

This directory persists on the host but is not source-controlled. `AzureBlobStorageService` exists as an alternative, but it is not registered by default and its credential/presigned-url path is not production-ready.

## Background work

The hosted `ScheduledJobRunner` and `WebhookDispatcher` are present, but current behavior is demo-level:

- The scheduler checks every minute and currently runs reminder/overdue jobs every check.
- Export processing is not invoked.
- Domain-event handlers are not registered, so domain events do not automatically publish webhooks.
- In-memory queues and presence state are lost on app-pool recycle.

For reliable production scheduling and delivery, move jobs and webhook publishing to durable infrastructure before depending on them.

## Deploy steps

1. Set production environment variables and secrets.
2. Apply database migrations.
3. Configure SMTP.
4. Build the frontend and copy `dist` into `FlowForge.API/wwwroot`.
5. Run backend and frontend verification.
6. Publish with Web Deploy, FTP/SFTP, or the provider's .NET build.
7. Restart the site and complete the verification checklist.

## Verification checklist

- `https://flowforge-app.runasp.net/` loads the SPA.
- Refreshing a deep link such as `/reports` does not return 404.
- `/health` reports Healthy.
- Login and organization switching work.
- A new invitation email points to `https://flowforge-app.runasp.net/accept-invitation?...`.
- Register-and-accept creates the membership with the invited role.
- SMTP diagnostics report the expected state.
- PWA installation and offline indicator work.
- SignalR connects using the configured transport fallback.

## Security notes

- Keep all secrets in environment variables or user secrets.
- Use a production SQL login with least privilege.
- Do not enable wildcard CORS for the same-origin deployment.
- Review webhook endpoint authorization and organization scoping before exposing subscription management broadly.
- Treat the current scheduler, Azure storage implementation, and automatic webhook publishing as hardening work.
